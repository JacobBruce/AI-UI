Install Guide

Download the latest release of AI UI, extract it, then follow the steps below.

You always need a Python environment for the AI engine. The Electron app itself is included in the release.

Quick Install (recommended)

Run the Python script from the extracted release folder (requires Python 3.12 - 3.14):

python install.py

On Linux you may need python3 install.py. The script creates the venv, installs the lite or full stack, and CUDA/CPU PyTorch (for full stack). When finished it writes/updates the config file at ~/.aiui/config.json.

python install.py --venv ~/aiui-venv --lite --yes
python install.py --venv C:\aiui-venv --full --torch cu128 --yes
Manual Install
Click to show install instructions for Windows
1. Python

Install Python (3.12.x recommended).

CUDA is optional but recommended if you have an Nvidia GPU:

  • CUDA Toolkit (12.8 recommended)

Open a command prompt and create a virtual environment:

python -m venv C:/venv

Replace C:/venv if you want the environment somewhere else. Activate it:

C:/venv/Scripts/activate.bat

If your GPU supports CUDA, install PyTorch before the other requirements (not needed if using lite requirements):

pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128

Then install the engine packages (replace C:/AI_UI with where you extracted the release; it should contain AI_UI.exe):

pip install -r C:/AI_UI/engine/requirements.txt

Use requirements-lite.txt instead of requirements.txt if you only want to use remote API's and don't need to run local models.

2. App packages (only if needed)

Skip this if your release already includes resources/app/app.bundle.js, vendor.bundle.js, and node_modules.

Otherwise install Node.js for Windows, then:

cd C:/AI_UI/resources/app
npm install
3. Launch

Start AI UI by launching AI_UI.exe. On the Settings tab, set Python Binary to your venv interpreter, e.g. C:/venv/Scripts/python.exe.

Click to show install instructions for Linux
1. Python

Ensure Python is installed (3.12.x recommended). On Debian/Ubuntu you may also need:

sudo apt install python3-pip python3.12-venv

Create and activate a virtual environment:

python3 -m venv ./venv
source ./venv/bin/activate

If your GPU supports CUDA, install PyTorch before the other requirements (not needed if using lite requirements):

pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128

Then install the engine packages (replace ./AI_UI with the extracted release path; it should contain the electron binary):

pip install -r ./AI_UI/engine/requirements.txt

Use requirements-lite.txt instead of requirements.txt if you only want to use remote API's and don't need to run local models.

2. App packages (only if needed)

Skip this if your release already includes resources/app/app.bundle.js, vendor.bundle.js, and node_modules.

Otherwise:

sudo apt install npm
cd AI_UI/resources/app
npm install
3. Chromium sandbox and launch

From the folder that contains the electron binary (not from another working directory):

sudo chown root:root ./chrome-sandbox
sudo chmod 4755 ./chrome-sandbox
./electron

If you prefer not to configure the sandbox helper:

./electron --no-sandbox

On the Settings tab, set Python Binary to your venv interpreter, e.g. path/to/venv/bin/python3.

Important Info

Node packages and bundles

The UI loads two prebuilt files:

  • resources/app/vendor.bundle.js - jQuery, markdown-it, highlight.js, KaTeX helpers, etc.
  • resources/app/app.bundle.js - AI UI’s own renderer code

Those are produced with esbuild (npm run build:vendor / npm run build:app). The Electron main process also needs packages under resources/app/node_modules (for example adm-zip for downloads).

For GitHub releases: the built *.bundle.js files and the packages under resources/app/node_modules are included with releases so you do not need Node.js.

If those files are missing (or you cloned the git repo), install Node.js and run:

cd path/to/AI_UI/resources/app
npm install

Windows Users

If you place AI UI into Program Files or another protected directory, you may need to run as administrator. Prefer a normal folder such as C:/AI_UI/.

Linux Users

Always start AI UI from the directory that contains the electron binary so relative paths resolve correctly.

The chrome-sandbox binary must be owned by root with mode 4755 for the Chromium sandbox, unless using --no-sandbox.

Upgrading

  1. Extract the new release over (or beside) your existing install.
  2. Re-run the install script against your existing venv: 
    python install.py --upgrade --venv path/to/venv --lite --yes
# or full (skip torch if already installed):
python install.py --upgrade --venv path/to/venv --full --torch skip --yes
    Or activate your Python venv and update packages manually: 
    pip install -U -r path/to/AI_UI/engine/requirements-lite.txt
# or full local stack:
pip install -U -r path/to/AI_UI/engine/requirements.txt
  3. If the release notes say Node dependencies changed, or app.bundle.js / vendor.bundle.js / node_modules are missing, run npm install again in resources/app (or python install.py --npm --venv ...).

Getting Started

  1. Launch AI UI and open the Settings tab.
  2. Set Engine Folder to the included engine directory if it's not auto-detected (contains aiui_engine.py).
  3. Confirm Python Binary points at your venv (.../Scripts/python.exe on Windows, .../bin/python3 on Linux).
  4. For remote chat: set Use Remote Backend to True and configure Remote Settings.
  5. For local chat: set Text Model (and optionally image/TTS/ASR models) to a local folder or Hugging Face model ID.
  6. Click APPLY, then check the Console tab if the engine does not start.

Local chat needs a text model in Hugging Face Transformers format (full requirements.txt stack). Image features need a Diffusers-format image model.

The image/TTS/ASR and avatar animation models can still be used with remote chat mode but will also require the full requirements.txt stack.

Remote Chat

The Remote Settings can point the Chat Bot at a remote API instead of loading a local text model. OpenAI-compatible endpoints use the OpenAI Python SDK; Anthropic Messages uses the Anthropic SDK.

  1. Set Use Remote Backend to True.
  2. Set Remote Model ID (required).
  3. Leave Remote Base URL empty for Hugging Face Inference Providers (https://router.huggingface.co/v1; use your HF token), or set a URL such as: 
    https://openrouter.ai/api/v1
https://api.openai.com/v1
http://localhost:11434/v1
  4. Optional: when Base URL is empty, set Remote Provider to pin a router provider (appended as model:provider).
  5. Set Remote API Key, or leave it empty to fall back to HuggingFace Access Token (OpenAI-compat / HF only - Anthropic requires an API key). Local serve/Ollama can omit both keys.
  6. Optional: set Remote Protocol to OpenAI (default; use for Hugging Face Inference Providers and OpenRouter) or Anthropic (Anthropic Messages).
  7. For Anthropic: leave Base URL empty for api.anthropic.com, set Model ID (e.g. claude-sonnet-4-6), enable Prompt Cache (default) for automatic ephemeral caching.
  8. Click APPLY. The engine will not load local chat weights while Remote is active.

File attachments: The attach dialog Vision control selects the local multimodal family and is disabled when Text Backend is Remote. Remote sends images (up to 10 MiB) and videos (up to 100 MiB) as image_url / video_url (http or base64) plus text-file contents; audio is skipped on remote.

Context Compaction

In AI Settings, Context Token Budget enables context summarization (aka context compaction) when the conversation length approaches that limit.

Set Context Token Budget to 0 to use classic Max Message Memory pruning (old information is lost, prefer summarization for long-range tasks).

To customize the context summarization instructions, place a compact_prompt.txt file in ~/.aiui.

Tool Use

With Enable Tool Use on, tool schemas are passed into the chat template via the tools argument (AI UI Template and Model Template).

The engine accepts JSON object, JSON array (multi-call), and XML <function=...> / <parameter=...> forms inside <tool_call>.

Use AI UI Template (no tool prompt) when a rule should teach the call format instead of the built-in template instructions.

A list of all the setup arguments which can be used for the Model Setup on the Settings tab.

torch_dtype (default: auto)

Description: The Torch data type used by the text generation model. Models using float16 will be faster and use less memory but are slightly lower quality than float32 models.

Valid Values: float32, float16, bfloat16

torch_compile (default: false)

Description: Enable to make PyTorch code run faster by using JIT-compiling. This can greatly increase generation speeds for some models. This feature may not be available on Windows platforms.

Valid Values: true, false

min_res_vram_mb (default: auto)

Description: Minimum VRAM to keep reserved as generation headroom and for loading small models on the fly. Default scales with GPU size from an 8GB baseline of 256. Freed before generation and reclaimed afterward. This only has an effect when the Compute Device is set to Auto.

Valid Values: any integer (megabytes)

gguf_file (default: none)

Description: The file name (not a full path) of a GGUF file to be used by the text generation model. This allows quantized GGUF models to be loaded. The Text Model setting should point to a location containing the gguf file and any other model files that may be required.

Valid Values: any string (gguf model file)

use_safetensors (default: none)

Description: If this argument isn't set the text generation model will try loading from a .safetensors file if one is available. If true the model will be forcibly loaded from a .safetensors file. If set to false the model will not try loading from safetensors.

Valid Values: true, false

custom_model_code (default: false)

Description: This allows the text generation model to use custom code. Technically it sets the trust_remote_code argument to true or false. Enable only with trusted models.

Valid Values: true, false

custom_token_code (default: false)

Description: This allows the text tokenizer to use custom code. Technically it sets the trust_remote_code argument to true or false. Enable only with trusted tokenizers.

Valid Values: true, false

load_in_8bit (default: false)

Description: Load the text generation model so it is quantized with 8-bit precision. Quantized models typically use much less memory and run faster but produce lower quality results.

Valid Values: true, false

use_chat_template (default: false)

Description: Some models can automatically format the chat log into the template they use. Prefer Template Format in AI Settings instead of this flag when possible. If the 'system' role is unsupported set Prompt Persistence to 'No Prompt' in the AI Settings of the chat bot.

Valid Values: true, false

use_aiui_template (default: false)

Description: Enables the AI UI custom chat template (with tool-call format instructions). Prefer Template Format in AI Settings: AI UI Template or AI UI Template (no tool prompt).

Valid Values: true, false

skip_special_tokens (default: true)

Description: If enabled the tokenizer will skip special tokens when decoding the output of the text generation model. Should usually be enabled.

Valid Values: true, false

cleanup_token_space (default: true)

Description: Enable to cleanup any spaces that were added when splitting the input text during the tokenization process. Should usually be enabled.

Valid Values: true, false

speech_recog_class (default: 'AutoModelForSpeechSeq2Seq')

Description: The transformers model class used for the speech recognition model (aka text-to-speech model). This setting should only be changed if you know what you are doing.

Valid Values: class name

text_lang_class (default: 'AutoModelForCausalLM')

Description: The transformers model class used for the text generation model. This only has an effect when Text Model Type is set to 'Auto Language Model' on the Settings tab.

Valid Values: class name

multi_modal_class (default: 'AutoModelForImageTextToText')

Description: The transformers model class used for the text generation model. This only has an effect when Text Model Type is set to 'Auto Multimodal Model' on the Settings tab.

Valid Values: class name

attn_implementation (default: 'sdpa')

Description: The attention implementation to use in the text generation model (if relevant). If available, SDPA will be used be default, otherwise the manual 'eager' implementation will be used.

Valid Values: 'eager', 'sdpa', 'flash_attention_2', 'flash_attention_3', 'flex_attention'

roles_append_str (default: ': ')

Description: The default chat log format appends a colon and a space after the usernames/roles (e.g. Human: hello). Use this to change the appended text. Use \n for new lines (e.g. roles_append_str=\n). This only has an effect when Template Format is set to None.

Valid Values: any string

anim_max_secs (default: 30)

Description: Maximum TTS audio length (seconds) for talking-avatar video. If the spoken reply is longer than this, video generation is skipped entirely (no partial clip) and audio-only playback is used instead. Set to 0 to disable the cap.

Valid Values: number >= 0

audio_max_chars (default: 4000)

Description: Maximum character length for TTS input (chat talk mode, Speech Gen, and read-aloud). Longer text skips speech entirely rather than generating a huge clip. Set to 0 for no soft cap (a hard 100000-character ceiling still applies).

Valid Values: integer >= 0

audio_max_new_tokens (default: 4096)

Description: Maximum TTS codec frames per chunk (~21.5 frames/s). Currently only used by Audio8 TTS. Generation normally stops earlier on EOS; this is only an upper bound. Audio8 clamps further by its context length.

Valid Values: positive integer

vocoder_model (default: none)

Description: The directory or Model ID of a speech vocoder model to be used by the text-to-speech model. Usually not needed and may not be supported by some TTS models.

Valid Values: any string (vocoder model folder)

tokenizer_model (default: none)

Description: The directory or Model ID of a tokenizer/processor for the text generation model. Most text generation models should come with tokenizers so this usually isn't needed.

Valid Values: any string (tokenizer model folder)

model_adapter (default: none)

Description: The directory or Model ID of an adapter for the text generation model. Adapters adjust the base model so it acts like a fine-tuned model without the need to download a full fine-tuned model.

Valid Values: any string (adapter model folder)

im_vae_file (default: none)

Description: The path to a Variational Auto-Encoder (VAE) model file to be used by the image generation model. Cannot be directory, must be path to a single model file.

Valid Values: any string (vae model file)

im_unet_file (default: none)

Description: The path to a Conditional U-Net model file to be used by the image generation model. Only this or im_tran_file should be set, not both. Cannot be directory, must be path to a single model file.

Valid Values: any string (vae model file)

im_tran_file (default: none)

Description: The path to a transformer model file to be used by the image generation model. Only applies to newer diffusion models such as Stable Diffusion 3. Cannot be directory, must be path to a single model file.

Valid Values: any string (transformer model file)

im_enc_file (default: none)

Description: The path to a text encoder model file to be used by the image generation model. Use im_enc2_file and im_enc3_file for the 2nd and 3rd text encoders. Cannot be directory, must be path to a single model file.

Valid Values: any string (text encoder model file)

im_config_file (default: none)

Description: The path to a .yaml config file which specifies the architecture for the image generation model. This only has an effect when loading single model files, can be useful for offline model loading.

Valid Values: any string (model config file)

im_variant (default: none)

Description: The model variant to use for the image generation model. For example, a value of 'fp16' is typically used to load the 16 bit floating point variant of a model.

Valid Values: any string (variant name)

im_model_class (default: none)

Description: The diffusers model class used for the image generation model. This argument overrides the Image Model Type setting. Only change this if you know what you are doing.

Valid Values: any string (class name)

im_lora_file (default: none)

Description: The file name (not a full path) of a LoRA model to be used as an adapter for the image generation model (e.g. pixel-art-xl.safetensors). Requires im_lora_dir to be set.

Valid Values: any string (lora model file)

im_lora_dir (default: none)

Description: The directory containing the LoRA adapter for the image generation model. This can also point to an online Hugging Face repository (e.g. nerijs/pixel-art-xl)

Valid Values: any string (lora model directory)

im_lora_scale (default: 1.0)

Description: Controls how much the LoRA adapter will influence the output of the image model. Higher values will give the LoRA more influence on the output. Should be a value between 0 and 2.

Valid Values: decimal number (0.0 to 2.0)

im_torch_dtype (default: float16)

Description: The Torch data type used by the image generation model. Models using float16 will be faster and use less memory but are slightly lower quality than float32 models.

Valid Values: float32, float16, bfloat16

im_res_vram_mb (default: auto)

Description: Extra VRAM to reserve for the image model so the text model does not fill that space at placement time. Default scales with GPU size from an 8GB baseline of 1536 when an image model path is set (0 otherwise). After the image model loads, only min_res_vram_mb stays reserved. This only has an effect when the Compute Device is set to Auto.

Valid Values: any integer (megabytes)

im_load_in_8bit (default: false)

Description: Load the image generation model with large components quantized using the bitsandbytes library. Does apply to some models loaded separately (using im_tran_file for example) but doesn't apply to GGUF files.

Valid Values: true, false

im_safety_check (default: true)

Description: Enable the safety checker to censor NSFW images produced by the image generation model. Set to false to disable the safety checker and prevent it from producing blank images.

Valid Values: true, false

im_cpu_offload (default: true)

Description: Enable CPU offloading for the image generation model to lower VRAM usage. Submodules of the model will be offloaded from the GPU to system memory when not in use. May reduce generation speed.

Valid Values: true, false

im_att_slicing (default: false)

Description: Enable attention slicing for the image generation model to lower VRAM usage. Splits the attention computations into steps instead of doing them all at once.

Valid Values: true, false

im_from_single_file (default: false)

Description: Force the image generation model to load from a single file such as a .safetensors or .ckpt file. Can be a local file path or a link to an online file (e.g. https://mysite.com/mymodel.safetensors)

Valid Values: true, false

im_local_files (default: false)

Description: Force the image generation model to load from local files only. This may be necessary to avoid errors when loading local models. Technically it sets the local_files_only argument to true or false.

Valid Values: true, false

im_use_safetensors (default: none)

Description: If this argument isn't set the image generation model will try loading from a .safetensors file if one is available. If true the model will be forcibly loaded from a .safetensors file. If set to false the model will not try loading from safetensors.

Valid Values: true, false
